# Function Ledger

## Purpose

This file records local capabilities added around Databao. It intentionally tracks only generic Data
Agent layers, not benchmark-specific parsers, task-family routes, or public-set memory.

## Update Rules

- Add or update this file whenever a local helper changes behavior, routing, logging, fallback, or
  answer-shaping semantics.
- Remove deprecated helpers instead of leaving stale active entries.
- Do not record concrete public task domains, file stems, entity names, category values, or copied
  benchmark phrasing as active strategies.
- Strategy provenance should be architectural: schema loading, document ingestion, answer contract,
  verification, timeout/logging, or scoring safety.

## Removed / Not Allowed

- Domain-specific document materializers and route families were removed from active code.
- No `public_optimized` mode exists.
- LLM structured planner fallback, LLM finalizer, candidate generator ensemble, lightweight Databao
  retry, schema/context prompt hint mode, context budget compact mode, semantic repair candidate flow,
  safe postprocess bonus, and ratio compact ablation switches were removed from the active runner
  after negative or inconclusive ablations.
- The reverted role-evidence ranking/final-guard experiment is intentionally not listed as active;
  generic signals should enter diagnostics first before they affect selection or pruning.
- The 2026-05-13 conservative answer-focus branch was not kept wholesale after restoring the
  high-score salvage runner. A few generic pieces were reintroduced one at a time after targeted
  checks: camelCase ID hint validation, answer-focus column targeting, strong display-column
  priority for entity answers, exact duplicate answer-row removal, and preservation of already
  aggregated multi-metric Databao outputs. The broad role-evidence/ranker rewrite remains removed.
- New helpers must be domain-agnostic unless they live outside production code for an explicit,
  temporary analysis notebook or experiment.
- 2026-05-15 cleanup removed three opt-in Databao-internal probe experiments that had measurable
  negative or near-zero score impact and were never enabled by default:
  - `DATABAO_INTERNAL_P0_RATIO_REJECT` (+ ratio promotion branch). Single Stage 2 test on
    `task_283` showed ratio reject destroyed the adapter aggregate-ratio verifier's rescue input
    (1.0 → 0.0). Adapter `apply_aggregate_ratio_verifier` and `apply_quoted_entity_ratio_repair`
    remain the load-bearing path for ratio/percentage shapes.
  - `DATABAO_INTERNAL_GROUNDING_PROBE` + helpers `_grounding_qualified_equalities`,
    `_resolve_alias_to_table`, `_build_grounding_probe_sql`, `_build_distinct_domain_probe_sql`.
    Default-on ablation caused four Hard tasks (`task_344`, `task_352`, `task_396`, `task_408`)
    to cross the 180 s task timeout because the verbose raw-CSV probe text inflated reject
    suggestions and triggered extra agent turns.
  - `DATABAO_INTERNAL_SCHEMA_GRAPH_PROBE` + helpers `_information_schema_columns`,
    `_find_lookup_tables`, `_select_key_columns`, `_format_probe_one_liner`,
    `_from_tables_in_sql`. Compressed one-liner output avoided the timeout regression and the
    cross-table mechanism verified correctly on `task_86` (reached the drivers lookup outside
    SQL's FROM), but the 3-run variance ablation showed probe-ON mean `32.33/49` vs probe-OFF
    `33.00/49` — net -0.67 inside the ±1 stdev variance band, with per-task wins balanced by
    per-task losses where the model picked a different SQL path that triggered the probe.
  Empty-result date probe stays in production (it produced a real cross-source pivot on
  `task_173` and adds no measurable runtime overhead).

## Strategy Map

| Layer | Strategy kind | Logged signal |
| --- | --- | --- |
| Context loading | generic | `context_summary`, schema graph table metadata |
| Query-time retrieval | generic | `retrieved_context`, selected tables/columns, sample rows, document snippets, join paths, retrieval confidence |
| Document extraction | generic or experimental_generic | `document_materialized_tables`, `document_extraction_used`, extracted rows/columns/confidence, metadata columns removed from agent table |
| Route choice | generic | `route_policy.route`, `route_policy.reason`, `candidate_source` |
| Complexity profiling | generic | `complexity_profile`, complexity score, uncertainty score |
| Context payload diagnostics | generic | `context_payload_profile`, registered sources, source sizes, document chars |
| Databao observation | generic diagnostic | `databao_internal_observation`, source kind, submit status, SQL/code operation flags, risk flags |
| Databao internal result salvage | generic execution-state repair | Local Databao clone tracks `last_non_empty_query_id/sql/df` so no-submit or latest-empty runs can return the previous non-empty query result. Inspired by hard missing/recursion cases where Databao had useful intermediate SQL but overwrote it before submit. |
| Databao internal submit/no-submit critique | generic diagnostic / experimental gate | Local Databao clone records submit risks such as empty result, ratio question without ratio evidence, aggregate question returning detail rows, count question without count-like output, unordered limit, wide non-list result, ungrounded numeric ID/code equality filters, disjunctive text filters that should anchor on one record, unresolved `link_to_*` identifiers, and no-submit intermediate returns. Default mode is `shadow`; `reject` is experimental and not enabled globally. Numeric grounding recognizes generic ordinal/ranking words so rank filters are not falsely flagged. Anchored lookup reject was tested on `task_355` and remains diagnostics-only after mixed results. `_latest_user_question` now strips the system-instruction prefix (anything before the last `Question:` marker) so question-keyword critiques (`asks_display`, `asks_ratio`, `asks_list`, etc.) do not false-positive on the runner's `"Prefer display, name, title, or label columns..."` prompt scaffolding. |
| Databao internal P0 submit gates | generic reject gate | Local Databao clone now promotes a narrow P0 reject set (`empty_submit_result`, `blank_display_needs_join`, `numeric_identifier_filter_needs_grounding`) to an actual submit rejection inside the lighthouse/separate graph, separate from the broader `DATABAO_INTERNAL_SUBMIT_CRITIQUE_MODE=reject` switch. Default-on via `DATABAO_INTERNAL_P0_GATES=1`; per-task budget capped by `DATABAO_INTERNAL_P0_MAX_REJECTIONS` (default 3) and the existing one-rejection-per-query-id guard. Ratio-without-ratio-evidence is intentionally excluded from the default P0 set (opt-in via `DATABAO_INTERNAL_P0_RATIO_REJECT=1`) because the adapter's aggregate/ratio verifier already rescues count-detail submits into percentage candidates, and forcing Databao to retry destroys that rescue input. New `_blank_display_critique` detects camelCase/snake_case display columns that are all-blank and lists identifier columns/samples Databao can resolve through joins. Empty-result suggestions append a date-format hint when the failing SQL filters a date/datetime column. Shadow-only `_unit_time_granularity_critique` and `_filter_audit_critique` add diagnostic flags without rejecting. Each reject is tagged with `reject_source=p0_gate` or `mode_reject` in the recorded critique so downstream analysis can attribute outcomes. |
| Databao internal empty-result probe | generic execution-state probe | When the `empty_submit_result` P0 gate fires and the failing SQL filters a column whose name contains `date`/`time`/`day`/`month`/`year`, the lighthouse executor automatically runs `SELECT DISTINCT <date_col> FROM <same FROM clause> LIMIT 5` and embeds the real samples in the reject ToolMessage. Helpers: `_date_filter_qualified_columns`, `_extract_from_clause`, `_build_date_probe_sql`. Suggestion text is explicitly directive ("rewrite the date literal and re-run the original query, do not submit these probe samples") to prevent the model from submitting the probe output. Submit critique records always include `sql_text` and `question_text` for post-hoc diagnostics; the previous "append only if flags" guard was removed so empty-flag submits remain visible in artifacts. Probe wiring is lighthouse-only because `lighthouse_salvage` is the default executor; separate-graph helpers exist for parity but the probe call site is not yet duplicated there. |
| Candidate validation | generic | `answer_contract.valid`, `should_repair`, row/column counts |
| Question feature extraction | generic | `question_features`, matched phrases, strong/weak terms, schema evidence, confidence |
| Candidate ranking | generic | `candidate_scores`, evidence reasons, selected candidate source, rejection reasons |
| Postprocess | generic | `postprocessing.transformations`, `applied_strategies` |
| Final guard | generic | `final_answer_guard.transformations`, metadata removed, contract before/after |
| Failure handling | generic | `failure_reason`, `databao_failure_type`, `prediction_written`, `scorable`, phase timings, timeout artifact |
